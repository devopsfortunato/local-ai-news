Liquid AI launches LFM3: six open-weight 2B-class models on one tri-hybrid backbone

Liquid AI released LFM3 on October 27 — text, vision, audio, omni and two decision models all derived from a shared 1.73B-parameter tri-hybrid backbone (gated short convolutions, sliding-window and global attention). The flagship LFM3-1.7B beats LFM2.5-2.6B with 35% fewer parameters, fits in about 1 GB at 4-bit, carries a 256K context window, and posts a dramatic agentic jump (38.42 vs 3.02 on WebArena-Verified). Weights ship in BF16/FP8/NVFP4/GGUF/MLX/ONNX with llama.cpp support already merged, and Ollama v0.40.12 added the family the same day.

Presents the first KV-cache codec targeting the prompt state that must be stored or moved for reuse, directly cutting KV-cache memory and bandwidth for local inference with cached prompts.

CoS-VQ: coordinated shared-scale vector quantization keeps low-bit LLM decoding simple

A low-bit weight VQ method that avoids inflating the effective coding dimension, keeping independent codeword lookup and local codeword updates simple for quantized local deployment.

Channel selection for MoE decoding needs no calibration data

Shows channel selectors for routed-expert weights can predict which intermediate channels matter without any calibration data, cutting memory reads in small-batch interactive decoding — the main MoE bottleneck on local hardware.

CrossInfer shares KV state across CPU/GPU/NPU engines on edge SoCs

A joint Wisconsin/Meta/CMU paper separates versioned stream context from per-engine KV state so heterogeneous engines can jointly run stateful VLM inference; on two RK3588 video streams it delivers 19.6% more throughput than the best single engine and cuts first-token latency 4.6x with cross-engine KV import.
